# New School – מתכננים למידה לבוחן

יחידת למידה בעברית וב־RTL, כ־10 דקות, לפי school-new-learning-page. HTML5, Bootstrap RTL 5.3.3 ו־JavaScript ES modules, ללא שלב build וללא ספריות נוספות.

## הפעלה

מתיקיית הפרויקט:

```sh
python3 -m http.server 8000
```

פתחו http://localhost:8000/index.html. אין לפתוח ב־file://: דפדפנים עשויים לחסום מודולים. כל הנכסים מקומיים, ולכן לאחר הפעלת השרת אין תלות באינטרנט. לעצירה: Ctrl+C.

## פרסום ב־GitHub Pages

קובצי האתר נשארים בתיקיית `src/`. התהליך `.github/workflows/pages.yml` מפרסם את תוכן התיקייה כך ש־`index.html` נמצא בשורש האתר הציבורי.

1. במאגר ב־GitHub פתחו **Settings → Pages → Build and deployment**.
2. בשדה **Source** בחרו **GitHub Actions** במקום **Deploy from a branch**. אין לבחור תיקיית פרסום במצב זה.
3. בצעו commit ו־push של קובץ התהליך לענף `main`. התהליך ירוץ בכל push לענף זה; ניתן להפעיל אותו גם דרך **Actions → Deploy website to GitHub Pages → Run workflow**.
4. המתינו לסיום מוצלח של הפריסה בלשונית **Actions**.

כתובת האתר לאחר פריסה מוצלחת: https://pearl-bettan.github.io/NewSchool/

אין צורך להעביר את קובצי האתר ל־`docs/` או לשורש המאגר. רק תוכן `src/` נכלל בפריסה; מסמכי המטלה והסקילים אינם חלק מחבילת האתר.

## מבנה

- index.html: תוכן, ניווט, חיווי התקדמות ושתי מסגרות הפעילויות.
- activities/study-plan.html: תוכנית נועה, פועלת גם בפני עצמה.
- activities/quiz.html: חמש שאלות, ולידציה, ניקוד ומשוב; פועלת גם בפני עצמה.
- css/styles.css: עיצוב משותף, התאמות מובייל, מיקוד ותנועה מופחתת.
- js/main.js: התקדמות, הודעות מאומתות ושינוי גובה המסגרות.
- js/activity-bridge.js: תקשורת באותו מקור ומעקב גובה התוכן.
- js/study-plan.js: נתוני ימים ויצירת אקורדיון.
- js/quiz-data.js: תוכן השאלות בלבד.
- js/quiz.js: הערכה וניקוד בפונקציות טהורות, ולצידן קוד תצוגה.
- assets/images, assets/vendor: SVG, Bootstrap, גופן ורישיונות.
- assets/media: שמורה למדיה, כרגע ללא סרטון.

## הנחות והחלטות יישום

המיומנות המבוקשת היא מקור הדרישות; הקבצים בתיקיית disingFiles הם דוגמאות והסברים של המורה, ואינם האפיון של היחידה. הבריף של קבוצה 1 והדרישות הכלליות של המטלה הם מקורות הדרישות. השמות נושא א/ב/ג נשמרו גם בדוגמאות היעד והחלוקה. נושא ג קצר וקל יותר; היום האחרון הוא 35 דקות לעומת 50 ו־65, ומתחיל בחזרה. דוגמת הזמנים במיומנות הותאמה כדי לממש את ההנחיה ליום אחרון קל. אין וידאו משום שלא סופק נכס מתאים, ואין מתכנן שבועי.

חיווי ההתקדמות מציין את השלב המוצג ואינו הוכחה להשלמת למידה. רף ההצלחה בשאלון 60%. בחירה מרובה: מספר הבחירות הנכונות פחות השגויות, חלקי מספר התשובות הנכונות, ברצפה של אפס. סדר: ניקוד לפי מיקומים, ללא כפילויות. שאלה 4 בודקת זיהוי פעולה קטנה ומוגדרת, ללא טווח שרירותי של מספר משימות. שאלה 5 היא הרכבת יעד משלושה שדות: פעולה, כמות ושעת סיום. אין ניתוח טקסט חופשי או ניקוד לפי אורך טקסט. בחירה בפעולה מוגדרת, כמות שלמה וחיובית ושעה תקינה מקבלת ניקוד מלא; הפעולה המעורפלת „ללמוד לבוחן” עם כמות ומועד מקבלת שני שלישים, ומשוב על המרכיב שחסר. כמות אינה מקבלת ניקוד לפי גודלה — על הלומד להתאים את ההיקף לזמן שברשותו. שדות חסרים או לא תקינים דורשים תיקון לפני הצגת ציון. אין שמירת תשובות, ואין SCORM בשלב 1; קיים hook יחיד ריק ב־quiz.js.

## אריזה ל־LMS

ארזו רק את index.html, activities/, css/, js/, assets/, README.md ו־CREDITS.md ל־ZIP, תוך שמירת המבנה. index.html צריך להיות בשורש הארכיון, ללא תיקיית עטיפה. אין לכלול את מסמכי המטלה או קובץ המיומנות.

להפעלת היחידה בחרו index.html כקובץ ההשקה. להפעלת פעילות בודדת ארזו עדיין את כל התלויות ובחרו activities/quiz.html או activities/study-plan.html כקובץ ההשקה (הקבצים בשורש החבילה היחסי). אם ה־LMS דורש קובץ השקה בשורש ממש, צרו שם עמוד מעטפת שמטמיע את הפעילות; אין להעביר את קובץ הפעילות ללא תיקון נתיביו. ZIP זה הוא חבילת אתר, אינו חבילת SCORM ואינו כולל manifest SCORM.

## הצעות לבדיקה ידנית

אלה תרחישים מוצעים; תיעוד התוצאות, טבלאות QA והחלטות ושימוש ב־AI מיועדים לכתיבה עצמאית של הסטודנטים.

- שליחה ריקה: הודעות חוסר לכל השאלות ומיקוד בשאלה הראשונה.
- שאלה 4: משימה מוגדרת לעומת משימה רחבה. שאלה 5: פעולה מעורפלת לעומת ברורה; כמות ריקה, 0, שבר ותווים שאינם מספר; שעת סיום חסרה. כמות 1 או 11 עם פעולה מוגדרת ושעה תקינה מתקבלת ללא ענישה שרירותית.
- תשובות מלאות, שגויות וחלקיות; כפילות בסדר המשימות; איפוס אחרי ניקוד.
- ניווט מקלדת בתפריט, אקורדיונים ושדות, כניסה ויציאה מהמסגרות; משוב בקורא מסך.
- 360/768/1200 פיקסלים, זום 200%, ריווח טקסט מוגדל ותנועה מופחתת.
- פתיחת כל פעילות בנפרד; הגדלת והקטנת גובה iframe באקורדיון, משוב ושינוי רוחב.
- חילוץ החבילה לתיקייה אחרת והפעלתה בשרת; אין בקשות רשת חיצוניות.
